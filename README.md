# slot-engine-esc

Учебное демо классического слота с полем 5 × 3: TypeScript, Vite и PixiJS 8. Комбинация меняется мгновенно. Символы A–E нарисованы через `Graphics` и `Text`, используются системные шрифты.

## Запуск

Нужен Node.js **22.18.0 или новее**.

```sh
npm install
npm run dev
```

Открой адрес, который напечатает Vite. Проверка и сборка:

```sh
npm test
npm run build
npm run preview
```

`build` проверяет TypeScript и создаёт каталог `dist`. `preview` показывает готовую сборку. Тесты выполняются встроенным раннером Node без браузера и PixiJS.

## Как пользоваться

Нажми «Начать», затем Spin. Enter или пробел запускают игру из меню и выполняют спин в слоте; Esc возвращает в меню. Во время выполнения спина повторный запуск и выход заблокированы.

При входе показаны первая комбинация и нулевой выигрыш. Результаты из `src/data/spins.json` идут по кругу: первый спин — 0, второй — 20, третий — снова 0. Возвращение в меню и новый вход сбрасывают последовательность.

JSON содержит готовую матрицу `[строка][барабан]` и `winAmount`. Выигрыш берётся из данных независимо от рисунка комбинации. Здесь нет расчёта выплат, RNG, сервера или сетевых запросов. Код SDK и игровые ассеты не используются.

## Устройство

| Модуль | Ответственность |
| --- | --- |
| `ecs/World.ts` | Создание и удаление числовых сущностей, хранение компонентов в типизированных `Map`, выбор сущностей по компонентам. |
| `ecs/components.ts` | Данные позиции, прямоугольника, текста, кнопки и ячейки. |
| `systems/GridSystem.ts` | Запись новой матрицы в 15 компонентов ячеек. |
| `systems/RenderSystem.ts` | Создание, синхронизация и освобождение Pixi-объектов. |
| `systems/InputSystem.ts` | Привязка кнопок к действиям активной сцены и снятие обработчиков. |
| `ui/factories.ts` | Создание панелей, подписей и кнопок из обычных ECS-компонентов. |
| `scenes/` | Меню, слот и управление жизненным циклом сцен. |
| `game/` | Источник результатов, автомат раунда, подготовка и последовательное исполнение действий. |

Компоненты содержат данные; поведение находится в системах. Pixi-объекты принадлежат слою отображения. Каждая сцена владеет собственным `World`, корневым контейнером, рендерером и вводом через `BaseScene`. `SceneManager` создаёт сцены через фабрики, переключает их и освобождает предыдущую сцену через `exit()` и `dispose()`.

```text
Spin → RoundController → FSM: running
     → RoundSource.peek() → buildActions(result)
     → ActionRunner
          → await setGrid → GridSystem
          → await setWin  → компонент текста
     → RoundSource.advance() → FSM: idle → перерисовка
```

`ActionRunner` выбирает обработчик по `type`, вызывает его и ждёт завершения перед следующим действием. Он не знает о кнопках или Pixi. Системы не читают общую очередь.

FSM разрешает переходы `idle → running → idle` и `running → error → running`. При ошибке сообщение показывается на экране; индекс результата сохраняется, следующий Spin повторяет ту же запись. Доступность кнопок выводится из состояния FSM.

Отрисовка выполняется по изменениям, включая переключение и изменение размера сцены. Постоянный игровой цикл и покадровый опрос очереди этому статичному демо не нужны.

## Как расширять

- **Сцена:** добавь имя в `SceneName` (`src/scenes/Scene.ts`), создай наследника `BaseScene` и зарегистрируй фабрику в `src/main.ts`. Переключайся через `context.navigate()`. Для новой кнопки добавь действие в `UIAction` (`ecs/components.ts`).
- **Компонент:** добавь данные в `Components` в `src/ecs/components.ts`, соответствующую `Map` в `World` и систему, работающую с этим набором компонентов. Компоненту не нужен собственный `update()`.
- **Символ:** добавь ключ и цвета в `SYMBOLS` в `src/game/symbols.ts`, затем используй ключ в JSON. Валидатор и отображение используют этот справочник.
- **Действие:** расширь объединение `Action` в `src/game/actions.ts`, добавь его в `buildActions()` и зарегистрируй обработчик при создании `ActionRunner` в `SlotScene`. Для асинхронной работы верни `Promise`, завершающийся после выполнения действия.

В тестах проверяются ECS, валидация и неизменность исходных результатов, последовательность обработчиков, остановка при ошибке, допустимые переходы FSM, защита от повторного спина и повтор результата после ошибки.
